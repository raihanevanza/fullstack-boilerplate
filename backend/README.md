# Backend

Go REST API for the fullstack boilerplate. It follows a layered layout (controller → use case → repository) and ships one complete example module, **products**, with JWT auth, role permissions, audit logging, i18n errors, Swagger and tests. The HTTP contract shared with the web and mobile clients is in [`../docs/API.md`](../docs/API.md). The database schema is in [`../db`](../db).

| Concern        | Technology                                                                   |
| -------------- | ---------------------------------------------------------------------------- |
| Language       | Go 1.22 (same version in `go.mod` and `Dockerfile`)                          |
| HTTP           | Gin 1.10 + `gin-contrib/cors`                                                |
| Database       | GORM 1.25 + SQL Server driver (`AppDb`)                                      |
| Auth           | JWT HS256 (`golang-jwt/jwt/v5`) + bcrypt                                     |
| Configuration  | Viper (`.env` file + environment variables) validated by `go-playground/validator` |
| Validation     | `go-playground/validator/v10`, messages translated                           |
| i18n           | `go-i18n` with `locales/en.yaml` (default) and `locales/id.yaml`, embedded   |
| Logging        | `pkg/logger`: zap + ECS JSON encoder to stdout                               |
| API docs       | Swaggo (`/swagger/index.html`, not served when `STAGE=PRODUCTION`)          |
| Tests          | testify, GoMock (`go.uber.org/mock`), `httptest`                             |

## Running locally

1. Start SQL Server and load the schema and dev seed: see [`../db/README.md`](../db/README.md).
2. `cp example.env .env`, then set `SQL_SERVER_URI` (URL-encode special characters in the password) and `JWT_SECRET` (`openssl rand -hex 32`).
3. `make run`. The API listens on `http://localhost:8080`, Swagger UI on `http://localhost:8080/swagger/index.html`.

```sh
curl -s localhost:8080/health
curl -s -X POST localhost:8080/api/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.com","password":"Password123!"}'
```

Dev accounts (password `Password123!`): `admin@example.com` (ADMIN) and `staff@example.com` (STAFF, read only).

### Docker

```sh
make docker-build
docker run --rm -p 8080:8080 --env-file .env boilerplate-backend:1.0.0
```

The image contains only the binary (locales are embedded). Configuration always comes from environment variables, and no `.env` is baked in. Inside a container, `localhost` is the container itself, so point `SQL_SERVER_URI` at `host.docker.internal` or at the database service name.

## Environment variables

Values are read from `.env` (from `ENV_FILE`, the working directory or the module root), and real environment variables override them. Startup fails on a missing or invalid value.

| Variable             | Required | Default               | Description                                                                 |
| -------------------- | -------- | --------------------- | --------------------------------------------------------------------------- |
| `PORT`               | no       | `8080`                | HTTP port                                                                   |
| `STAGE`              | no       | `DEVELOPMENT`         | `DEVELOPMENT`, `STAGING` or `PRODUCTION`. Development logs SQL and debug lines and allows any localhost CORS origin. Production hides Swagger. |
| `SERVICE_NAME`       | no       | `boilerplate-backend` | Log field and JWT issuer (`iss`)                                            |
| `CORS_ALLOW_ORIGINS` | no       | (empty = any origin)  | Comma-separated browser origins                                             |
| `TRUSTED_PROXIES`    | no       | (empty = none)        | Comma-separated proxy IPs/CIDRs whose `X-Forwarded-For` is trusted          |
| `SQL_SERVER_URI`     | yes      |                       | `sqlserver://user:pass@host:1433?database=AppDb&encrypt=disable`            |
| `JWT_SECRET`         | yes      |                       | At least 32 characters                                                      |
| `JWT_TTL`            | no       | `8h`                  | Access token lifetime (Go duration)                                         |

## Conventions

### Errors and i18n

Use cases return `*apperr.Error` values for expected failures (`apperr.ErrNotFound`, `apperr.ErrDuplicate`, ...). `response.Fail` turns them into the envelope with the right status, and translates `title` and `message` from `locales/<lang>.yaml` using the request's `Accept-Language` (English when the header is missing or unsupported). Any other error is logged and returned as a generic 500.

- New error code: `var ErrX = apperr.New("err_x", http.StatusConflict)` plus `err_x.title` and `err_x.message` in **both** locale files.
- Dynamic message: `apperr.ErrDuplicate.WithMessage("msg.duplicate_sku", map[string]any{"Sku": sku})`.
- Validation failures become `400 bad_request` with a translated message naming the JSON field (`price is required.`).
- Tests fail when the locale files have different keys or a declared code has no translation.

### Transactions

Use `repository.Transactor` (implemented by `datasource.WithTransaction`). The transaction is carried in the `ctx` passed to the callback, and every repository method calls `Datasource.DB(ctx)`, so any repository called with that ctx joins the transaction automatically. Returning an error, or panicking, rolls everything back.

```go
err := usecase.Transactor.WithTransaction(ctx, func(ctx context.Context) error {
	if err := usecase.ProductRepository.Create(ctx, &product); err != nil {
		return err
	}
	// Same transaction: the audit row is never written without the product, and vice versa.
	return usecase.AuditRepository.Log(ctx, actor, constantvar.AUDIT_CREATE, constantvar.ENTITY_PRODUCT, product.ID, nil, after)
})
```

Always use the callback's `ctx` inside it, not the outer one. Nested `WithTransaction` calls reuse the outer transaction.

### Permissions

The role → permission map lives only in `pkg/constantvar` (`ROLE_PERMISSIONS`). `GET /api/auth/me` returns the caller's permissions, so clients never hard-code roles. Protect a route with `middleware.Require(constantvar.PERM_X)` after `middleware.Auth`:

```go
write := middleware.Require(constantvar.PERM_PRODUCT_WRITE)
group.POST("", write, c.Create)
```

To add a permission, declare a `PERM_*` constant, add it to the roles in `ROLE_PERMISSIONS` and use it in the route. To add a role, insert it into `dbo.Roles` (`db/init/01_schema.sql`) and add it to `ROLE_PERMISSIONS`.

### Soft delete and duplicates

Entities with a `gorm.DeletedAt` field are soft-deleted, and GORM hides deleted rows automatically. Unique values use filtered unique indexes (`WHERE DeletedAt IS NULL`), so a deleted SKU can be reused. A violation surfaces as SQL Server error 2601/2627. Check it with `datasource.IsUniqueViolation(err)` and return `apperr.ErrDuplicate` (409).

### Logging

`pkg/logger` writes one JSON object per line to stdout (ECS field names, debug level in development). Every request is logged by `middleware.requestLogger` with method, path, status, latency, client IP, platform (`X-Platform`), user ID, and request/response bodies. `password` and `access_token` are redacted at any depth, and large bodies are truncated.

## Adding a new module

Example: `customers`.

1. **Schema**: add the table to `db/init/01_schema.sql` (`CreatedAt` default `SYSUTCDATETIME()`, `UpdatedAt`, `DeletedAt`, filtered unique indexes, CHECK constraints), and optionally seed rows in `02_seed_dev.sql`.
2. **Entity**: `pkg/model/entity/customer.go` with explicit `gorm:"column:..."` tags and `TableName()`.
3. **Request/response**: `pkg/model/request/customer.go` (with `validate` tags and an optional `Normalize()`) and `pkg/model/response/customer.go` (`NewCustomerResponse`).
4. **Repository**: `pkg/repository/customer.go`, an interface plus implementation that always uses `Datasource.DB(ctx)`.
5. **Use case**: `pkg/usecase/customer.go`. Wrap writes and their audit log in `Transactor.WithTransaction`, and map errors to `apperr` codes.
6. **Errors and messages**: new `apperr` codes or `msg.*` keys in `locales/en.yaml` **and** `locales/id.yaml`.
7. **Controller**: `api/controller/customer.go` with Swagger annotations, then add it to `controller.Controller`.
8. **Permission**: `PERM_CUSTOMER_WRITE` in `pkg/constantvar`, mapped to roles.
9. **Route**: register the group in `api/route/route.go` (reads behind `Auth`, writes behind `Require`).
10. **Registry**: build the repository, use case and controller in `api/registry/registry.go`.
11. **Mocks**: `make mock`.
12. **Swagger**: `make swag`.
13. **Tests**: use case tests with repository mocks (`pkg/usecase/*_test.go`) and controller tests through the real router (`api/controller/*_test.go`).
14. **Contract**: document the endpoints in `docs/API.md` so the web and mobile clients can follow.
